# 執筆前の思考手順(骨子の作り方)

本文を書く前に、以下を順に決める。ここで決めたことは執筆中に変更しない。

## 1. 読者モデルを固定する

審査委員を想定して書く。前提は次の3つ。

- **専門が少しずれている。** 同じ大分野だが自分の研究テーマの専門家ではない。分野内輪の略語・暗黙の前提は通じない。
- **疲れていて時間がない。** 数十件を短時間で読む。2回読まないと分からない文は、読まれない文である。
- **採点表を持っている。** 審査基準の項目ごとに根拠を探しながら読む。根拠が見つからない項目は低評価になる。

したがって、すべての文は「1回読みで理解でき、審査基準のどれかに根拠を与える」ことを目指す。

## 2. 中心主張を1文にする

書き始める前に、次の形式で1文を作る。

> 本研究は【未解明の問題X】を【手法Y】により明らかにし、【学術的・社会的帰結Z】への道を開く。

この1文が書けないうちは骨子を作らない。X・Y・Zのどれかが曖昧なら、ユーザーに質問して埋める。この文は概要セクションの核になり、全段落はこの文のどこかを支える役割を持つ。

## 3. 審査基準との対応表を作る

種目別 structure-*.md にある審査観点を縦に並べ、「どのセクションのどの段落で答えるか」を割り当てる。**どの段落にも割り当てられない観点があれば、骨子の欠陥である。** 段落を追加するか既存段落に役割を足す。

## 4. 「問い」をファネル構造で設計する

背景セクションは次の5ステップで狭めていく。各ステップ1〜2文が目安。

1. **既知(known)**: 分野で確立していること。広く始めるが2文まで
2. **未知(unknown)**: それにもかかわらず分かっていないこと
3. **問い(question)**: 未知を研究可能な形に絞った核心の問い
4. **接近(approach)**: なぜ今・なぜ自分ならこの問いに答えられるか(予備データ、独自技術、着想)
5. **見返り(payoff)**: 答えが出ると何が変わるか

よくある失敗は 1 が長く 2〜3 が薄いこと。トークンも紙幅も 2〜4 に厚く配分する。

## 5. 段落を設計する

セクションごとに、段落を次の形式で列挙する。

```
段落n: [トピックセンテンス(主張を1文で)]
  根拠: [データ / 文献 / 論理 のどれで支えるか + 具体的中身]
  接続: [前の段落との論理関係: だから / しかし / 具体的には / 一方で]
  対応: [審査基準のどの観点に効くか]
```

規則:

- 1段落=1主張。2つ言いたいなら2段落に分ける。
- トピックセンテンスは段落の先頭に置く前提で書く。段落の先頭だけ拾い読みしても論旨が通ることを確認する(審査委員は実際にそう読む)。
- 「重要である」「注目されている」で終わる段落を作らない。何がどこまで分かっていて何が分かっていないかを述べる。

## 6. 独自性は対比で示す

「独自性が高い」と自称しない。次の3点セットで示す。

1. 従来のアプローチは X である(公平に要約する)
2. 本研究は Y である(差分を1点に絞る)
3. Y が可能なのは Z があるからだ(自分だけが持つ予備データ・技術・視点)

Z がないと「思いつき」に読まれる。Z に当たる材料が素材にない場合はユーザーに確認する。

## 7. 反論を先回りする

審査委員が抱く典型的懸念を1つ以上、骨子の段階で特定し、答える段落を用意する。

- 実現可能性(本当にできるのか)→ 予備データ、段階的計画、うまくいかない場合の代替案
- 新規性(既にやられていないか)→ 直近の研究動向との差分を明示
- 規模の妥当性(この予算・期間で必要か)→ 計画と経費の対応

## 8. 骨子の出力形式

以上をまとめ、ユーザーに次の形式で提示して承認を得る。

```
【中心主張】(1文)
【セクション構成】(様式のセクション × 段落数 × 文字数配分)
【段落設計】(上記5の形式で全段落)
【審査基準対応表】(観点 → 段落番号)
【ユーザーへの確認事項】(素材で埋められなかった穴)
```
