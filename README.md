# grant-writing-ja

日本語の研究費申請書を、**高品質かつ低トークン**で執筆・改稿するための Claude Code スキルです。
Fable 5 の申請書ライティングの思考過程を、Codex・Antigravity など他の CLI エージェントでも再現できるよう、
Claude 固有機能に依存しないプレーンな Markdown だけで構成しています。

対応種目:

- **科研費**(基盤 B/C・若手)
- **JST**(さきがけ・創発的研究支援事業)
- **民間財団助成**

## これは何をするスキルか

「書き直しを減らす」のではなく「書く前の設計で品質を決める」という方針で、以下を自動化します。

1. **設計(骨子)** — 中心主張の一文化、段落ごとのトピックセンテンス、審査基準との対応表を、安価な箇条書きで先に作る
2. **一発書き** — 承認された骨子を肉付けして本文を一度で書く
3. **自己校閲** — チェックリストで点検し、不合格の文だけを差分修正する

本文の全文再生成を禁止し、参照ファイルは該当フェーズのものだけ読むことで、トークン消費を抑えます。

## 導入

### Claude Code の場合

このリポジトリを、Claude が探すスキル置き場(`~/.claude/skills/` もしくは `~/.agents/skills/`)に置きます。

```bash
git clone <このリポジトリのURL> ~/.agents/skills/grant-writing-ja
```

Windows で `~/.agents/skills/` から `~/.claude/skills/` へリンクを張る場合は、
`ln -s` ではなくジャンクションを使ってください(Git Bash の `ln -s` は Windows で実コピーになるため)。

```bat
cmd.exe /c "mklink /D C:\Users\<user>\.claude\skills\grant-writing-ja C:\Users\<user>\.agents\skills\grant-writing-ja"
```

### Codex・Antigravity など他エージェントの場合

スキル置き場の概念がないエージェントでは、`SKILL.md` のパスを直接指示に含めて読ませます。

```
このファイルの手順に従って申請書を書いて: <clone先>/grant-writing-ja/SKILL.md
```

`SKILL.md` は冒頭でワークフローを説明し、必要な参照ファイルを各フェーズで読むよう指示しているため、
エージェントは `SKILL.md` を起点に `references/` を自力でたどれます。

## 使い方

種目と様式、研究内容の素材(研究メモ・過去申請書・論文など)を添えて依頼します。発話例:

- 「科研費・基盤(C)の申請書を書きたい。様式はこれ、研究内容はこのメモ」
- 「さきがけの研究構想を作りたい。領域は○○」
- 「財団助成に出す800字の文章を書いて」
- 「この背景の段落を審査基準に合うよう改善して」

エージェントはまず入力を確認し、**骨子を提示して承認を求めてから**本文を書きます。
骨子の段階で方向性を直すことが、最も安く品質を上げる方法です。

## 自分の過去申請書を手本にする

`examples/` ディレクトリに、採択済みなど自分の過去申請書の抜粋を `.md` で置くと、
執筆フェーズで**文体の最優先の手本**として読み込まれ、語彙とリズムが自分の文体に寄ります。

- ファイル名に種目を含めると、その種目の執筆時に選んで参照されます
  - 例: `kakenhi-wakate-2024.md`, `jst-sakigake-2023.md`
- 初期状態では `examples/_placeholder.txt` のみが置かれています(手本は未登録)

## ファイル構成

```
grant-writing-ja/
├── SKILL.md                       スキル本体(ワークフローと絶対規則)
├── README.md                      このファイル(人間向けの導入)
├── references/
│   ├── thinking.md                執筆前の思考手順(読者モデル・主張の一文化・段落設計)
│   ├── structure-kakenhi.md       科研費の様式構成と審査基準対応
│   ├── structure-jst.md           JSTさきがけ・創発の構成と評価観点
│   ├── structure-zaidan.md        民間財団助成の構成
│   ├── style.md                   日本語文体規範とNG→OK対比例
│   └── checklist.md               自己校閲チェックリスト
└── examples/
    └── _placeholder.txt           手本の置き方の説明(手本を置いたら削除可)
```

## 設計思想(低トークンの仕組み)

- **設計優先** — 高価な本文の前に、安価な箇条書きで論理と構成を固める
- **一発書き** — 承認済みの骨子から本文を一度で書き、書き直しを前提にしない
- **差分校閲** — 校閲は同一ターンで行い、直すのは不合格の文だけ
- **段階的読み込み** — 参照ファイルは該当フェーズのものだけ開く
- **枠の事前確定** — 文字数・行数制限を執筆前に確定し、枠あふれによる再執筆を防ぐ
